📊 Discussion on Current Evaluation Limitations

Current evaluation protocols use Hungarian matching to align predictions with ground truth before computing metrics (IoU w/ Hungarian). While this ensures optimal matching, it masks a critical issue: False Positives.

⚠️ Problem:

  • Real-world applications have no ground truth
  • False positives (extra detections) degrade downstream tasks (such as 4D reconstruction)
  • Hungarian matching "hides" these false positives in evaluation
  • Methods like Flow-SAM (SOTA method) may have high IoU but many false positives

🎯 Better Way:

  • Current evaluation omits false positives, so we also report a metric (IoU w/o Hungarian) that is computed without Hungarian matching

✨ Our Advantage:

  • Our method produces fewer false positives
  • Better suited for practical usage
  • IoU w/o Hungarian captures this benefit, and shows other methods' redundant false positives
